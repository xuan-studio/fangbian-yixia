# 办公小浣熊编号提示词

使用方法：现场每完成一个检查点再发下一条。不要把全部提示词一次性发送。小浣熊如果提出重构框架，优先要求它在现有 Starter 上增量修改。

## 00｜接管与护栏（0–5 分钟）

```text
接管当前“方便一下”Starter。先阅读 README.md、app/types.ts、public/data/toilet-record.schema.json 和 docs/60-minute-replay.md，再运行项目。

硬约束：
1. 不重写项目框架，不更换 deck.gl / MapLibre 技术路线。
2. 不生成小红书评价或评分；保留现有 12 个有来源的榜单场所点，新增事实必须能回指原帖或公开 POI。
3. 缺失字段写 null，界面显示“待核实”，未知不能当成 false。
4. 保持离线概念地图和公开厕所数据可用。
5. 医疗功能必须标注纯娱乐，不给诊断；红旗症状提示就医。

先报告：启动地址、公开厕所数量、优质厕所数量、构建状态。若均正常，再进入下一步。
```

## 01｜地图主链检查（5–15 分钟）

```text
检查首页 3D 地图主链：公开厕所柱、上海轮廓、区域筛选、开放状态、蹲厕、坐厕、无障碍、第三卫生间、来源筛选、点击详情。逐项修复阻塞问题。

不要添加模拟优质厕所。在线底图不可用时，必须自动切换离线概念图，并保留筛选、详情和紧急推荐。

完成后运行 lint，并只报告失败项或“全部通过”。
```

## 02｜紧急降级找厕（15–25 分钟）

```text
检查“憋不住了”交互，确保四级降级按顺序可见且可点击：
L1 保留全部筛选；
L2 放宽设施，仅优先已确认 24 小时；
L3 忽略未知设施，选择最近公开点；
L4 在地图也不可用时给出地铁、酒店、医院、商场服务台的人工求助方案。

距离只能标注为直线估算，不伪装精确导航。修复后说明默认演示点与各级结果。
```

## 03｜真实空状态与导入器（25–34 分钟）

```text
检查优质榜单：现有 12 个场所点必须显示“具体楼层待核实”。平台证据、Mock 评论和现场评论必须使用不同徽标；Mock 不得参与评分、设施确认或可信度。验证导入器能读取 JSON 数组或 {records: []}，至少要求 name、longitude/latitude（或 coordinates 对象）。

导入后的记录统一标记 premium_xhs + pending_verification；合法记录应自动出现金色 3D 柱、榜单和详情。不要把导入内容写入公开数据文件。

检查评论区楼内定位：用户可以提交楼层、方位和行走说明；投稿只进入候选池。真实确认、演示确认和反对票分开计数，达到 3 人共识才显示上线。任何包含演示票的候选只能显示“演示上线”。
```

## 04｜AI 乐子观察（34–42 分钟）

```text
检查排泄记录弹窗：布里斯托类型、耗时、文字描述、便血/黑便、持续腹痛均可输入。输出必须是娱乐型观察，不得声称诊断。

如果选择便血、黑便或持续/剧烈腹痛，停止普通乐子分析并明确提示尽快联系医生，严重时急诊。记录只保存在当前浏览会话，不上传。
```

## 05｜商业叙事与 3 分钟路演（42–49 分钟）

```text
检查页面下方商业区与“3 分钟演示”弹窗。保留三条商业路径：
1. 商场厕所体验 SaaS；
2. 明确标注且不影响紧急排序的推广位；
3. 只有明确同意后才参与的匿名聚合研究。

把南京德基广场表达为“案例启发/待引用核实”，不要写未经核验的营收或排名结论。确保演示路径能在 3 分钟讲完。
```

## 06｜最终验收（49–57 分钟）

```text
执行最终验收：
1. npm run lint
2. npm test
3. 检查 public/data/premium-toilets.json 仍是合法真实状态
4. 检查 public/sw.js 已缓存首页、三份数据文件和 Schema
5. 检查桌面宽屏与手机宽度没有横向溢出

只修复会影响演示的问题，不做大规模重构。输出“通过/失败”表格和剩余风险。
```

## 07｜锁定演示（57–60 分钟）

```text
停止新增功能。给我一份 60 秒上台前清单：启动地址、首个点击目标、金色榜单点、四级降级触发点、AI 安全提示触发方式、商业闭环结尾句。确认 12 个榜单点仍为“具体楼层待核实”。不要再改代码，除非构建失败。
```

## 有真实小红书内容时的追加提示词

```text
下面内容由用户合法提供。只根据原文或截图中明确出现的信息结构化，不推测厕所名称、坐标、评分、设施或开放时间。无法确认的字段写 null。每条保留 sourceRef；评论只做短摘要，不长篇复制原文。输出严格符合 public/data/toilet-record.schema.json 的 {status:"ready", records:[...]} JSON，并先校验再导入。
```
